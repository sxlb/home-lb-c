01 · 设计原则

视觉气质与基调

一句话定位：克制、清晰、专业的工具感——后台不是展示前台，目标是让管理动作一目了然、可预期、无歧义。

分层克制

一眼辨层级
3层中性灰文字 + 1 主色 + 1 警示色，禁用五彩斑斓的“高饱和”信息噪音

规格统一

消除三类混用
4套组件统一：Header / 保存 / 空状态 / 列表交互，同类面板用同一种表达

焦点明确

操作可预期
1个主要 CTA 每面板，read 为主的面板不出现无关写入口，降低误操作

质感细腻

玻璃拟态呼应前台
8-16px 圆角 + 柔和投影 + 细节状态反馈，延续前台玻璃语言但更平面克制
02 · 现状诊断

当前不一致的关键痛点

这些是新设计语言首先要解决的“结构性”问题（细颗粒审美问题在 §5 佐以具体数值给出）。

维度现存问题影响严重度
标题层级页面标题头（page.tsx 生成）与卡片 <CardTitle> 双重标题，Profile/Theme/Music 尤甚层级叠床架屋、视线失焦高
Header 布局三种风格混用：无按钮 / 标题+右按钮 / 图标+标题+描述同类面板识别成本高高
保存交互三种模式：底部+悬浮 / dirty 提示不一致（Links 有、FriendLinks 无）/ 无 dirty保存预期不统一中
空状态居中图标、虚线框、图表内占位、无占位 —— 至少 4 种写法空态表达混乱、缺少引导中
列表交互链接面板=列表+行内编辑+批量保存；公告=表单常驻+行内操作同为列表管理却交互割裂中
功能归位内容管理塞 8 项；系统设置仅 1 项 —— 分组失衡导航扫视效率低中
折叠实现Profile 用原生 <details>，Theme 用封装 SectionBlock，两套写法视觉与源码都不统一低

05 · 面板统一规范

面板通用组件规约

这是消除三类混用的核心：抽象 PanelHeader / SaveBar / EmptyState / LinkList 四类通用件，让所有面板复用同一套视觉与交互。

A · PanelHeader · 页头（统一右操作区）
站点公告
发布 / 编辑公告，前台上方展示
＋发布公告
  • 所有面板注册页头标题/描述；主 CTA（新增/保存/刷新）统一在右侧
  • 只读面板（日志/统计/健康）主 CTA 为“刷新”
  • 取消“图标+标题+描述“式冗余页头（图标留给面包屑/卡片已足够）
B · SaveBar · 脏状态与保存（统一表达）
● 有未保存的更改保存
  • 写面板统一“底部脏提示条 + 页头右侧保存“；不再各自为政（FriendLinks 补齐 dirty）
  • 删除“右下角悬浮保存”，收敛操作位置、降低遮挡感
  • 保存成功：toast「已保存」+ 脏态清除 + 服务端回填（沿用现有职责分工）
C · EmptyState · 空状态（统一四种写法）
◎

暂无数据 · 点击右上角新增，或返回查看引导

  • 统一：居中图标底圆 + 主文案 + 引导性次文案
  • 统计/图表空态沿用同一组件（移除图表内零散占位）
  • 规格 py-12 · 46px 底圆(bg-muted) · 14px 文案
D · LinkList · 列表批量管理（公告对齐链接面板）
  • 公告面板改为 LinksPanel 式“行内展开编辑 + 批量保存“，与社交/网站/友链完全同构
  • 字段差异由 props 驱动（标题/内容/置顶/上下线 → name/icon/url/tip）
  • 排序统一：移除“拖拽手柄图标但实际按 sort 排“的误导视觉，改为明确的“上移/下移 + 排序值”
  • 删除确认从 window.confirm 升级为 sonner 内联确认，保持反馈体系统一

面板细节质感建议（微调项，含数值）

位置建议改动（CSS 级）
卡片容器border-radius:12px · border:1px solid #e7e9ee · box-shadow 用上文阴影token，全面板统一
折叠分组统一为 SectionBlock（删除 Profile 手写 <details>），标题 13px/600 + 圆点指示色
表单控件select/input 统一 height 36px + focus ring 2px #4f5cd933，借 admin-select 类统一作用域
行内数字排序/统计数字统一 font-variant-numeric:tabular-nums，避免跳动
危险操作恢复/清空等统一 destructive（红描边+浅红底 hover），与 toast 内联确认互补
动效过渡统一 150-200ms ease-out；尊重 prefers-reduced-motion
06 · 功能分类重排

导航信息架构（新分组）

把 13 项平铺收敛为 4 组均衡分组，“做内容”与“配系统”“看运维”三类心智清晰分离，并在系统设置抽取“高级配置”承载 SEO/脚本/页脚等进阶项。

运维与统计

归位说明

  • 天气设置 从“内容管理”迁至“外观与功能”——它是站点功能参数，与内容展示无关
  • SEO/自定义脚本/页脚 从“站点信息”的繁重表单中拆出，单独“高级配置”减少首屏信息密度与误改风险
  • 账号设置 更名“账号与安全”，定位更清晰、为后续安全项（登录设备、密码强度）预留空间
  • 链接三合一 归入“链接管理”Tab 页，导航从 13 减到约 12 项但分组更有结构
07 · 缺失功能规划

四项高价值功能缺口

每项按 需求背景 → 方案 → 数据/埋点 → 落地建议 展开（仅设计，不落地）。

F1 · 后台快捷入口

背景 / 为“改完即看”打通前后台，当前无任何回到前台的入口
低成本 纯前端 · 网页无 Schema
高频 每次编辑后回看
P1 首轮可交付

方案：① 左侧栏底部常驻“打开主页”（新标签打开 siteUrl 或首页）；② 页头操作区增加“复制主页地址”小图标按钮；③ 保存成功的 toast 增加“去前台查看”快捷动作。

埋点：前台快捷入口点击次 / 保存后跳转转化率。

F2 · 媒体图库管理

背景 / 目前只能逐张上传、无集中管理，容易重复上传、找不到已用图
中成本 新模型 + 1 面板 + 上传/删除/URL API
价值高 头像/logo/壁纸/链接图混用
P2 建议第二轮

方案：新增 ImageAsset 模型（id·url·fileName·mimeType·size·width·height·usage·createdAt），上传时自动登记；后台新增“媒体库”面板：网格浏览、按类型过滤、复制 URL、删除（并提示引用处）、支持拖拽多选。

埋点：上传量 / 复用率（同一 URL 被引用数）/ 删除操作数。

Schema 建议

model ImageAsset {
  id        Int      @id @default(autoincrement())
  url       String   @unique   // 存储相对路径
  fileName  String
  mimeType  String   @default("image/png")
  size      Int      @default(0)
  width     Int      @default(0)
  height    Int      @default(0)
  usage     String   @default("") // avatar/siteicon/link/wallpaper/logo
  createdAt DateTime @default(now())
  @@index([mimeType])
}

F3 · 操作日志导出与清理

背景 / 日志只能看不能带走，长久堆积也无法归档
低成本 复用查询，加导出/清理 API
运维价值 审计归档
P2 需鉴权+确认

方案：日志面板增加“导出 CSV”（按当前筛选条件导出为 UTF-8 BOM，Excel 兼容）与“清理历史”（输入时间段/全部，二次确认）；导出走带鉴权的下载端点，清理记录一条操作日志。

埋点：导出次数 / 清理触发与清量。

API 建议

GET  /api/logs/export?module=&username=&from=&to=&action=   // 下载 CSV（鉴权）
POST /api/logs/clean  { from, to }                          // 清理（二次确认，写审计日志）

F4 · 访问统计深度分析

背景 / 当前仅有 PV/UV 概览与小时分布，缺地域、来源与内容热度洞察
中成本 需 IP→地域映射（内置库或第三方）
价值高 了解访客画像
P3 建议明年迭代

方案：统计面板增加 ① 地域分布（省/市，IP 库映射，聚合进 VisitRecord 或独立聚合表） ② 来源分析（分桶 referrerDomain：直接 / 搜索引擎 / 社交 / 外链） ③ 热门链接/页面 Top N（复用 SiteLinkClick + 新增页面计数） ④ 时段对比（本周 vs 上周）。

埋点：UV 去重口径、单页停留、跳转事件（如已有则复用）。

数据建议

-- VisitRecord 补列（可选，避免引入独立 IP 库依赖）
country String @default("")  region String @default("")  city String @default("")
-- 或新增统计聚合表：VisitGeo(date,region,pv,uv) · VisitReferrer(date,type)
-- 热门页面复用现有统计中间件，不必新建模型即可达 Top 链接
08 · 实施路线

分阶段落地建议

按风险从低到高、收益从快到久排序，每阶段可独立验收上线。

P0 · 一致性收敛 风险最低

  • 消除页面/卡片双标题；统一 Header（PanelHeader）
  • 统一 SaveBar 与 dirty 表达（FriendLinks 补齐）
  • 统一 EmptyState 空态组件
  • 统一折叠分组为 SectionBlock

P1 · 视觉语言升级 投资回报高

  • 落地 §3 全套 Design Tokens 与 §5 质感微调
  • 布局骨架重构（导航收敛 + 页头统一 + 快捷入口 F1）
  • 排版节奏、间距、阴影逐步替换

P2 · 功能补全 中风险

  • 媒体图库 F2（新模型 + 面板 + 上传/删除/复制 API）
  • 日志导出与清理 F3（导出 CSV + 清理审计）

P3 · 数据洞察 需评估

  • 统计深度分析 F4（地域映射方案选型后实施）
  • 公告面板最终对齐 LinkList 交互
